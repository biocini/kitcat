# Identity types

The identity type `x =_A y` is the type of **identifications** (paths) between
`x` and `y`. An element `p : x =_A y` is a *witness* that `x` and `y` are equal,
not a mere truth value — there may be many identifications of `x` with `y`, and
`p = q` between two of them is again a meaningful type. Iterating this gives the
tower of identity types that makes every type an ∞-groupoid.

This digest covers: the identity type as an inductive *family* generated by
`refl`; based path induction (`ind-=`) and the unbased variant; the groupoid
operations `p ∙ q`, `p⁻¹` and their laws (up to higher paths, never
judgmentally); `ap f` and its functoriality; `tr B p`; `apd f p` and dependent
paths (`tr B p y = z`); contractibility of the singleton `Σ (x:A). a = x`; and
the contrasting worked example of the `add`-laws on ℕ, proved by ordinary
ℕ-induction rather than path induction.

Keep the two equalities apart (see dependent-type-theory.md): `≡` is judgmental
equality — holds by computation rules, is not a type, cannot be hypothesized or
proved; `=` is the identity type — its elements must be *constructed*, usually
by path induction or by induction on a type like ℕ.

## Key definitions

### The identity type as an inductive family

For `A` a type and `a : A`, the **identity type** of `A` at `a` is the inductive
family of types `a =_A x` indexed by `x : A`, with a single constructor
`refl a : a =_A a`. An element of `a = x` is called an *identification* of `a`
with `x`, or a *path* from `a` to `x`. (The family is also written `Id_A`; the
subscript `A` is usually dropped.) Note the asymmetry: the family ranges over
all `x : A`, but the constructor only lands in the diagonal fiber `a = a`.

Formal rules:

```
Formation:     Γ ⊢ a : A                          ⇒  Γ, x:A ⊢ a =_A x  type
Introduction:  Γ ⊢ a : A                          ⇒  Γ ⊢ refl a : a =_A a
Elimination:   Γ, x:A, p:a =_A x ⊢ P(x,p) type    ⇒  Γ ⊢ ind-=_a : P(a, refl a) → Π (x:A). Π (p:a =_A x). P(x,p)
Computation:   Γ ⊢ u : P(a, refl a)               ⇒  Γ ⊢ ind-=_a(u, a, refl a) ≡ u
```

**Based path induction** (`ind-=`, also called *identification elimination*):
to prove or construct something for all `x : A` and all `p : a = x`, with `a`
*fixed*, it suffices to handle the case `refl a`. The computation rule is
judgmental, so anything defined by path induction computes on `refl`.

### The binary (unbased) identity type

One may also form the identity type at a variable: `Γ, x:A, y:A ⊢ x =_A y type`,
with constructor `refl x : x =_A x` indexed by `x : A`, and similar elimination
and computation rules. The resulting induction principle: for any family
`P(x, y, p)` over `x y : A` and `p : x = y`,

```
ind-= : (Π (x:A). P(x, x, refl x)) → Π (x y : A). Π (p : x = y). P(x, y, p)
ind-=(u, x, x, refl x) ≡ u(x)
```

Use this form when both endpoints may vary.

### Concatenation and inverses

```
concat : Π (x y z : A). (x = y) → (y = z) → (x = z)        -- infix: p ∙ q
inv    : Π (x y : A). (x = y) → (y = x)                    -- postfix: p⁻¹
```

`p ∙ q` is in diagrammatic order: first `p : x = y`, then `q : y = z`, landing
in `x = z`.

Construction of `concat`: by based path induction on the *first* path. Define
`f(x) := ind-=_x(λz. id) : Π (y:A). (x = y) → Π (z:A). (y = z) → (x = z)` — at
`refl x` the required term is the identity function on `x = z` — then swap
arguments: `concat(p, q) := f(x, y, p, z, q)`. By the computation rule,
`refl x ∙ q ≡ q` (judgmental!). Construction of `inv`: by path induction,
`(refl x)⁻¹ := refl x` (judgmental).

### Action on paths of functions

For `f : A → B`:

```
ap f : Π (x y : A). (x = y) → (f x = f y)       ap f (refl x) := refl (f x)
```

Every function preserves identifications — a form of continuity. Two companion
operations, also by path induction:

```
ap-id A       : Π (x y : A) (p : x = y). p = ap id p
ap-comp(f, g) : Π (x y : A) (p : x = y). ap g (ap f p) = ap (g ∘ f) p
```

### Transport

For `B` a type family over `A`:

```
tr B : Π (x y : A). (x = y) → (B x → B y)       tr B (refl x) := id
```

so `tr B (refl x, b) ≡ b` judgmentally. Moral (*indiscernibility of
identicals*): type theory cannot distinguish identified elements — for any
family `B` over `A`, an element of `B x` yields an element of `B y` along
`p : x = y`.

### Dependent action on paths (apd) and paths over `p`

For a dependent `f : Π (a:A). B(a)` and `p : x = y`, the naive comparison
`f x = f y` is ill-typed: `f x : B x` while `f y : B y`. Transport first:

```
apd f p : tr B p (f x) = f y                    apd f (refl x) := refl (f x)
```

(the base case works since `tr B (refl x) (f x) ≡ f x`). In general, for
`y : B x` and `z : B y'`, the type `tr B p y = z` (for `p : x = y'`) is a
**dependent path** or **path over `p`** — the dependent notion of
identification across fibers. It is the target type of `apd`, and it is what
later chapters use to characterize identity types of Σ-types and to formulate
induction principles of higher inductive types (see circle.md).

## Key results

### The groupoidal structure of types

All laws are proved by path induction; all hold only up to higher
identifications. For `p : x = y`, `q : y = z`, `r : z = w`:

| Name | Type | Base case (at `refl`) |
|---|---|---|
| `assoc(p,q,r)` | `(p ∙ q) ∙ r = p ∙ (q ∙ r)` | `refl (q ∙ r)` |
| `left-unit(p)` | `refl x ∙ p = p` | `refl (refl x)` |
| `right-unit(p)` | `p ∙ refl y = p` | `refl (refl x)` |
| `left-inv(p)` | `p⁻¹ ∙ p = refl y` | `refl (refl x)` |
| `right-inv(p)` | `p ∙ p⁻¹ = refl x` | `refl (refl x)` |

Proof pattern (associativity as the model): induct on `p`. At `refl x` both
sides compute judgmentally to `q ∙ r` (since `refl x ∙ q ≡ q`), so
`assoc(refl x, q, r) := refl (q ∙ r)`. The inverse laws similarly use
`(refl x)⁻¹ ≡ refl x` and `refl x ∙ refl x ≡ refl x`.

Remark: with `concat` defined as above, the *left* unit law is even judgmental
(`refl x ∙ p ≡ p`), so `left-unit(p)` could be `refl p`; the *right* unit law is
genuinely propositional. Rijke defines both uniformly by path induction.

These laws are identifications *between* identifications — one rung up the
tower of identity types, which extends without bound.

### Functoriality of `ap`

```
ap-refl(f, x)    : ap f (refl x) = refl (f x)          -- judgmental; witness refl (refl (f x))
ap-inv(f, p)     : ap f (p⁻¹) = (ap f p)⁻¹             -- path induction on p
ap-concat(f,p,q) : ap f (p ∙ q) = ap f p ∙ ap f q      -- path induction on p; at refl both sides ≡ ap f q
```

With `ap-id` and `ap-comp`: `ap f` preserves the whole groupoid structure (up
to higher paths) — a functor of ∞-groupoids.

### Coherence: the Mac Lane pentagon (exercise)

For four consecutive identifications `p : a = b`, `q : b = c`, `r : c = d`,
`s : d = e`, the five re-associations

```
α₁ : ((p ∙ q) ∙ r) ∙ s = (p ∙ (q ∙ r)) ∙ s      -- assoc(p,q,r) whiskered on the right by s
α₂ : (p ∙ (q ∙ r)) ∙ s = p ∙ ((q ∙ r) ∙ s)      -- assoc(p, q ∙ r, s)
α₃ : p ∙ ((q ∙ r) ∙ s) = p ∙ (q ∙ (r ∙ s))      -- assoc(q,r,s) whiskered on the left by p
α₄ : ((p ∙ q) ∙ r) ∙ s = (p ∙ q) ∙ (r ∙ s)      -- assoc(p ∙ q, r, s)
α₅ : (p ∙ q) ∙ (r ∙ s) = p ∙ (q ∙ (r ∙ s))      -- assoc(p, q, r ∙ s)
```

commute: `(α₁ ∙ α₂) ∙ α₃ = α₄ ∙ α₅`. (Whiskering can be built with `ap` of
concatenation-with-a-fixed-path, e.g. `α₁ := ap (λt. t ∙ s) (assoc p q r)`.)
So any two re-association routes between the same parenthesizations are
themselves identified — the first nontrivial coherence of the groupoid laws.

### Further groupoid operations (exercises)

```
distributive-inv-concat(p,q) : (p ∙ q)⁻¹ = q⁻¹ ∙ p⁻¹
inv-con(p,q,r) : (p ∙ q = r) → (q = p⁻¹ ∙ r)
con-inv(p,q,r) : (p ∙ q = r) → (p = r ∙ q⁻¹)
lift B (p, b)  : (a , b) = (x , tr B p b)      -- in Σ (x:A). B(x), for p : a = x, b : B a
```

`inv-con`/`con-inv` rearrange path equations (cancel a path from one side).
`lift` is the path-lifting property of fibrations: a path in the base lifts to
the total space from any prescribed point of the fiber. All are proved by path
induction on a path chosen so the `refl` case computes.

### Contractibility of the singleton

**Proposition.** For `a : A` and any `y : Σ (x:A). a = x`, there is an
identification `(a , refl a) = y`.

**Proof.** By Σ-induction it suffices to treat `y ≡ (x , p)` with `x : A` and
`p : a = x`. By based path induction on `p` it then suffices to give
`(a , refl a) = (a , refl a)`, which is reflexivity. ∎

So `Σ (x:A). a = x` has, up to identification, exactly one element — such types
are called **contractible** (equivalences.md). This is the precise sense in
which `refl` is unique: the *pair* `(a , refl a)` is unique in the total space,
not in any single fiber `a = a`. The same Σ-induction-then-path-induction
pattern underlies based path induction itself, and later the fundamental
theorem of identity types (fundamental-theorem.md).

### Worked example: the laws of addition on ℕ (ordinary induction!)

Recall `add` is defined by ℕ-induction in its **second** argument:
`add m 0 ≡ m` and `add m (succ n) ≡ succ (add m n)`. These two judgmental
equalities are *all* we know about `add`. Two of the six laws below coincide
with them and hold by `refl`; the other four require ℕ-induction — never path
induction, since the goals are equations between concrete terms, not properties
of arbitrary paths.

| Law | Statement | Proof |
|---|---|---|
| `right-unit-add` | `n + 0 = n` | `refl n` (judgmental) |
| `left-unit-add` | `0 + n = n` | induction on `n` |
| `right-succ-add` | `m + succ n = succ (m + n)` | `refl` (judgmental) |
| `left-succ-add` | `succ m + n = succ (m + n)` | induction on `n` |
| `assoc-add` | `(m + n) + k = m + (n + k)` | induction on `k` |
| `comm-add` | `m + n = n + m` | induction on `m`, using unit + successor laws |

**`left-unit-add`**, in detail. Base: `0 + 0 = 0` by `refl 0` (computes). Step:
given `p : 0 + n = n`, the goal `0 + succ n = succ n` computes to
`succ (0 + n) = succ n` (since `add` recurses on the second argument), so
`ap succ p` closes it: `left-unit-add := ind-ℕ(refl 0, λp. ap succ p)`.

**`left-succ-add`**, step: from `p : succ m + n = succ (m + n)`, the goal
computes on both sides — `succ m + succ n ≡ succ (succ m + n)` and
`succ (m + succ n) ≡ succ (succ (m + n))` — so `ap succ p` closes it.

**`assoc-add`**, step: from `p : (m + n) + k = m + (n + k)`, both sides of the
goal compute to `succ`-headed terms, so `ap succ p` closes it. Induction is on
`k` precisely because that is the variable both sides recurse on.

**`comm-add`**. Base: `0 + n = n + 0` does not compute on either side — chain
the unit laws: `left-unit-add(n) ∙ right-unit-add(n)⁻¹`. Step: from
`p : m + n = n + m`, chain:

```
succ m + n = succ (m + n)      -- left-succ-add(m, n)
           = succ (n + m)      -- ap succ p
           ≡ n + succ m        -- judgmental
```

The successor laws are proved first precisely to serve as these intermediate
bridges. Exercises in the same style: the semi-ring laws of `mul` on ℕ, and the
unit/successor/associativity/commutativity/inverse laws of addition on ℤ, plus
`succ_ℤ (pred_ℤ k) = k` and `pred_ℤ (succ_ℤ k) = k` (see number-theory.md,
groups.md).

## Reasoning idioms

1. **To construct an operation on all paths out of a fixed `a`** — i.e. for a
   motive `P(x, p)` over `x : A` and `p : a = x` — use based path induction and
   handle the case `refl a`. The computation rule then makes your definition
   compute judgmentally on `refl`.
2. **Both endpoints free?** Use the unbased form: motive `P(x, y, p)`, handle
   `refl x : x = x`.
3. **The base-case-must-compute heuristic.** Groupoid-law proofs work because
   at `refl` the two sides become *judgmentally* equal via the computation
   rules of the operations involved; the law is then `refl` of the common
   reduct. Before inducting on a path, substitute `refl` mentally: if the sides
   do not compute to the same term, induct on a different path (or generalize
   the goal). `concat` inducts on its *first* argument precisely so that
   `refl ∙ q ≡ q`.
4. **Path algebra by equational chains.** Identify two paths by chaining
   explicit identifications with `∙` (and `⁻¹` to run a law backwards),
   justifying each step: a groupoid law, congruence via `ap f`, rearrangement
   via `inv-con`/`con-inv`, or a previously proved lemma.
5. **Path induction vs type induction — choose by goal shape.** Quantified over
   arbitrary `p : x = y` with the endpoint a variable → path induction. An
   equation between specific expressions built from constructors of an
   inductive type (numerals, `add`/`mul` terms) → that type's own induction
   principle. Path induction proves things about *all* identifications; it says
   nothing about concrete loops or concrete numerals.
6. **The ℕ equation-proving loop.** (i) Try `refl`: does the goal hold
   judgmentally by the functions' computation rules? (ii) If not, induct on the
   variable the function recurses on, so both sides compute. (iii) In the step,
   reduce both sides until constructor-headed, then apply `ap` of the
   constructor to the induction hypothesis. (iv) If a side does not compute
   (recursion on the other argument), bridge with a previously proved lemma
   via `∙`.
7. **Moving along paths.** Transfer a construction between fibers with
   `tr B p`; state equality of dependent data `y : B x`, `z : B y'` as a
   path-over `tr B p y = z`; show a dependent map respects `p` with `apd f p`;
   lift a base path into a Σ-type with `lift`.
8. **Singleton elimination.** With `(x , p) : Σ (x:A). a = x` in context, you
   may assume it is `(a , refl a)` — the content of singleton contractibility,
   and the engine behind based path induction.

## Pitfalls

1. **Axiom K / UIP is not provable.** You cannot construct `p = refl a` for an
   arbitrary `p : a = a`: path induction requires a *free* endpoint, and in
   `p : a = a` both endpoints are the fixed `a`. The family `a = x` is
   inductively generated by `refl a`; the single fiber `a = a` is **not**.
   There are types with nontrivial loop spaces (S¹, circle.md). Never
   "path-induct on a loop".
2. **`=` is not `≡`.** The groupoid laws are identifications, not judgmental
   equalities: `right-unit p : p ∙ refl y = p` cannot serve where a definitional
   unfolding is required. Conversely, definitional coincidences like
   `refl ∙ q ≡ q` depend on exactly how the operation was defined (which
   argument it inducts on) — know your definitions, and don't build others'
   proof obligations on such quirks.
3. **No path induction on a specific path.** `ind-=` eliminates a *variable*
   path over a free endpoint; it never says anything about one concrete `p`.
4. **Ill-typed dependent comparison.** For `f : Π (x:A). B(x)`, the expression
   `f x = f y` is not a type. Transport first: `apd f p : tr B p (f x) = f y`.
5. **Transport does not compute on a generic path.** `tr B (refl x, b) ≡ b`
   judgmentally, but `tr B p b` with variable `p` is stuck — treat it
   abstractly, or characterize transport in the specific family at hand (later
   chapters do this for Π-, Σ-, ℕ-, and universe-valued families).
6. **Orientation slips.** `p ∙ q` needs `p : x = y` and `q : y = z` and lands in
   `x = z` (diagrammatic order). The inverse laws are `p⁻¹ ∙ p = refl y` and
   `p ∙ p⁻¹ = refl x` — note *which* endpoint's `refl` appears; swapping them
   makes the base case unprovable by `refl`.
7. **Uniqueness of `refl` lives in the total space only.** `(a , refl a)` is
   unique in `Σ (x:A). a = x` — not `p = refl a` in the fiber `a = a`.
   Confusing the two is the axiom K fallacy again.
8. **Wrong induction variable on ℕ.** `add` recurses on its second argument, so
   associativity goes by induction on `k`; induction on `m` leaves both sides
   stuck. Match the induction variable to the recursion argument of the
   functions in the goal.
