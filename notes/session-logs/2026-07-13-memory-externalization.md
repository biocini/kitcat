### 3.1 The coherence-verbosity canary + the factoring corollary
### (Lane, 2026-07-10)

Coherence-proof verbosity — pt-points, σ/α pairs, bridge plumbing,
reassociation bookkeeping — is a CANARY that the relevant
structures are not yet formulated correctly; the coherence work
stands as proof of concept until the formulation makes the tower
collapse. Lane's sense here is attuned by years of doing type
theory by hand, pre-agents; treat it as a calibrated instrument,
not a hunch. Evidence: verbosity never got "managed" in this
library — it evaporated under reformulation (face₃₅ → ap-comp when
the action became definitional; the flat reshape showed sub-comp
and the face₃₅ crux to be one fact; vindicated a third time in the
07-10/11 collapse arc). How to apply: the PRIMARY criterion for any
record/formulation design is "does the coherence tower collapse
under it" — transplanting the same face plumbing at higher
abstraction is a fail; read "Stratum C is irreducible, do not
chase" as a statement about the current formulation, not the
mathematics. COROLLARY (Lane, sharply): "it only factors the
skeleton" is an argument FOR factoring, never against — repeated
shared scaffolding IS the verbosity; a named helper is vocabulary,
not cost; never weigh helper-definition lines against inline
savings by raw count. The standard: each proof site shows ONLY its
site-specific content; every shared token moves into a named
pattern.

### 3.2 Soundness over idiom (Lane, 2026-07-11)

Justifying an error-suppression patch (`|| true` on rg pipelines)
as "the script's own existing idiom" is unacceptable: local idiom
governs *style* (naming, comment density, structure), never
correctness standards. An unsound pattern already present in a file
is a defect to fix, not a license to replicate. When a benign
special case needs tolerating, handle it explicitly and name it
(e.g. `rg_allow_empty() { rg "$@" || [ $? -eq 1 ]; }` — no-match is
an empty set; every other failure propagates with stderr intact).
The remediation pattern for discovered idiom-level unsoundness is a
dedicated antipattern review of the surface (the bin/ review,
2026-07-11). Note: `bin/` practices this today (`rg_allow_empty` in
bin/lint); the rule itself is written nowhere in the layer.

### 3.3 Monoidal native derivation — never deloop (Lane, 2026-07)

For `Cat.Monoidal`, derive all monoidal structure natively in terms
of `tensor-emb` and the derived binary tensor — mirroring the
*shape* of the Cat.Type/Cat.Coherence proofs restated directly in
the tensor vocabulary. Do NOT present the object level by delooping
onto `Cat.Type.category` (ob = Unit). Lane, verbatim: "the route
through the category definition is pretty silly... I said to do an
analogous argument not to lift the category machinery wholesale."
The delooping typechecks — keep it mentally as a correctness oracle
only. Prune vestigial arguments rather than transcribing
faithfully: index-erasure leaves dead binders/parameters, and some
are dead even in the original (e.g. an unused unit-equivalence
hypothesis) — dropping one genuinely strengthens the native
statement, so surface those to Lane rather than silently copying.
Lane flagged that the first port under-cleaned these.

### 3.4 The fresh-start principle (Lane, 2026-07-11, binding)

All workflow guidelines are stated POSITIVELY, as if followed all
along: no references to old conventions, no deprecation notes, no
migration commentary anywhere in the context layer. Where an
existing artifact diverges from a new convention, MODIFY the
artifact — never explain the divergence. Boundary: docs/gloss.md
ledger history is data (theorem provenance), not deprecated
convention. The layer practices this principle throughout, but it
is stated nowhere in it — a suite-maintainer authoring the next
workflow has no written rule to follow.

### 3.5 erased-cubical path→equiv: transport-equiv, never ua
### (recorded 2026-07-08)

To turn a path of types `A ≡ B` into an equivalence (or to promote
a J-built path-of-types characterization into a `≃`) under `--safe
--erased-cubical`, use `transport-equiv` from
`Core.Transport.Properties`; do NOT reach for
`Core.Univalence`/`ua`/`idtoeqv` — that module is `--cubical`
(needs Glue), so importing it breaks the consuming module's flag
profile. Exemplar: `Cat.Iso` (`hom-PathP≃square` via a double-J
path of types + `transport-equiv`; no univalence for `idtoiso`).
Styleguide check (this sweep): docs/styleguide.md's new
"Cubical-native proofs" bullet (2026-07-13) covers the
prefer-native-over-J preference, and the pragma bullet covers where
`--cubical` is allowed, but neither states this flag-profile recipe
— the convention remains unencoded; a candidate line for the
styleguide's cubical bullets.

### 3.6 The standing dispatch directive (Lane, 2026-07-10 —
### partially encoded)

Do NOT drip-feed direction into a long-running background agent
(each finalization pass answers a stale brief); settle direction
in-conversation first, then spawn a FRESH agent with one complete
self-contained brief per consultation. STANDING DIRECTIVE: no agent
dispatches until the design is nailed down in-conversation — token
discipline; the conversation is the design workspace, agents
execute settled specs. Partially encoded: `.agents/CLAUDE.md`
Delegation requires complete self-contained briefs; the
design-settled-first gate itself is unstated.
